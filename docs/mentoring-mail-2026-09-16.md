■ 프로젝트 개요
병동 회진에 동행하는 자율주행 로봇이 의사–환자 대화를 수음하여 환자용 진료 요약(SBAR 형식)을 생성하고,
의사가 1-tap으로 검수한 내용만 종이 메모 또는 환자 스마트폰으로 즉시 전달하는 시스템입니다.
모든 음성·언어 처리는 Jetson Orin NX 16GB 위에서 온디바이스로 수행하여 환자 데이터가 외부로 나가지 않도록 설계했습니다.

■ 진행 현황 (2026-09-16 기준)
1) 음성 → 요약 파이프라인
 - NVIDIA Riva 한국어 ASR을 Jetson에서 구동, ReSpeaker 마이크 실시간 인식 및 의학용어(메트포르민 등) 단어 부스팅 적용
 - Riva vs Whisper 비교: 원거리 음성에서 Whisper는 그럴듯한 문장을 날조하는 반면 Riva는 인식 실패가 드러나는 특성 확인 → 의료용으로 Riva 채택
 - 온디바이스 LLM 요약 벤치마크: 8B 모델은 품질은 양호하나 300토큰 생성에 24초, 2B 모델은 빠르나 환각(수치 반대 해석 등) 다수
   → "회진 종료 후 3초 내 요약"은 일괄 생성으로 불가능함을 실측으로 확인하고, 회진 중 실시간 증분 요약 구조로 설계 변경
 - 의사 검수 웹 화면 구현: 승인 전에는 출력·QR·인쇄 경로가 모두 차단(403)되도록 human-in-the-loop 강제
2) 로봇 주행
 - 1/5 스케일 조향식 차량 + Arduino Mega 모터 제어 펌웨어(워치독 자동정지 포함) + 키보드/게임패드 원격조종 완료
 - 2D 라이다(STL-27L) 연결·장착 방향 보정 완료, 조이스틱 주행으로 병동 복도 규모의 첫 점유격자 지도 생성(그래프 SLAM, 순수 Python)
 - 지도 기반 자율주행(측위 + A* 경로계획 + 조향 제어) 코드 작성 완료, 실차 검증은 이번 주 진행 예정
3) 산출물: 벤치마크 보고서, 시연 대본(3분), 배선·프로토콜·설정 문서화

■ 현재 고민 중인 문제 (멘토링에서 여쭙고 싶은 점)
1. 차량에 바퀴 엔코더가 없어 라이다 정합만으로 오도메트리를 대체하고 있습니다. 특징이 적은 긴 복도에서 위치 추정이 흐려지는데,
   엔코더/IMU를 추가하는 것이 맞을지, 아니면 대회 범위에서는 라이다 기반으로 충분한지 판단을 듣고 싶습니다.
2. 조향이 각도 센서 없는 DC 모터(개루프)라, 측위로 추정한 요레이트를 피드백해 조향 펄스를 주는 방식으로 제어하고 있습니다.
   조향 각도 센서(포텐셔미터/서보 교체)를 추가할지, 제어기 설계로 버틸지에 대한 조언을 구합니다.
3. Jetson 16GB 메모리 예산(ASR 약 3.7GB + LLM 3~5GB + 주행 스택)이 빠듯하여 "주행 모드"와 "회진 모드"를 분리 운영하고 있습니다.
   시연 관점에서 이 분리가 타당한지, 더 나은 구성이 있을지 의견을 듣고 싶습니다.
4. 평가 설계: 가짜 회진 대화 50건으로 요약 보존율·환각률을 측정할 계획인데, 심사에서 설득력 있는 평가 지표와 실험 설계에 대한 조언을 부탁드립니다.
5. 의료기기 소프트웨어(IEC 62304) 관점의 human-in-the-loop 설계와 환자 데이터 처리에 대해 발표에서 어느 수준까지 다루는 것이 적절할지 여쭙고 싶습니다.
